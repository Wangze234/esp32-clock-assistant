## 1. 项目目标与验收标准

### 最终成品
一台放在桌上的常亮设备，具备：

1. 时间（时 / 分 / 秒）+ 日期 + 星期 + 农历日历
2. 当地天气（当前温度、天气现象、今日最高最低、未来 3 天）
3. 室内温湿度（外接传感器实测）
4. 大模型语音助手：唤醒词 → 提问 → 语音回答，屏幕同步显示对话
5. 装进通用塑料外壳，7×24 小时稳定运行

### 学习目标
把下面这些链路各走通一遍（这也是选模块化 DIY 而不是一体板的原因）：

- SPI 驱动屏幕（TFT_eSPI）
- I2C 驱动传感器（AHT20 / DS3231）
- WiFi + HTTP + JSON 解析
- NTP 对时与时区处理
- I2S 数字音频输入 / 输出
- LVGL 图形界面 + 中文字体
- 多任务（FreeRTOS）与内存管理（PSRAM）

### 总体验收
- [ ] 断电重启后 10 秒内自动联网、对时、刷新天气
- [ ] 屏幕无闪烁、无残影，中文显示正常
- [ ] 连续运行 72 小时不死机、不重启
- [ ] 语音唤醒成功率 ≥ 80%（安静室内、1 米内）

### 3.2 电源接法

```
USB 5V ──┬── ESP32-S3 VIN ──┬── MAX98357A VIN   (功放走 5V)
         │                  └── 板载 LDO → 3V3 ──┬── 屏幕 VCC
         │                                      ├── INMP441 VDD
         │                                      ├── AHT20 VCC
         │                                      └── DS3231 VCC
         └── GND 全部共地（这一点最容易忘）
```

> ⚠️ 功放峰值电流可达 500mA。若喇叭一响就重启，说明供电不足：换 5V/2A 以上电源，并在功放 VIN 与 GND 之间并一个 100–470µF 电解电容。

### 3.3 接线顺序（按这个顺序接，出错好排查）

1. **只接屏幕** → 上电 → 跑点屏例程 → 成功后再接下一个
2. **接 I2C**（AHT20 + DS3231）→ 跑 I2C 扫描，确认 `0x38`、`0x68`
3. **接话筒**（INMP441）→ 只做录音回放
4. **接功放 + 喇叭**（MAX98357A）→ 与话筒一起测回环
5. 每接一个模块，都在 §8 日志里记一笔

### 3.4 外壳开孔尺寸

以 **100×68×50mm** 通用塑料盒 + 2.8" 屏为例：

| 项目 | 尺寸 / 位置 |
|---|---|
| 屏幕可视区 | 约 57.6 × 43.2 mm |
| 盒盖开孔 | **58 × 44 mm**，居中偏上 |
| 屏幕 PCB | 约 50 × 86 mm，长度方向沿盒子 100mm 边放置 |
| 喇叭孔 | 直径 3mm 小孔阵列，或 40mm 圆孔，开在侧面/底部 |
| 麦克风孔 | 直径 2mm，远离喇叭 ≥ 5cm，避免啸叫 |
| 散热 | 顶部或侧面开几排 3mm 孔 |

开孔方法：画线 → 美工刀沿边反复划透 → 掰断 → 锉刀修边。**不要用热风枪**，会把塑料吹变形。

### 3.5 屏幕 J1 供电跳线（必读）

MSP2807 背面有一个焊盘跳线 **J1**，决定板载 XC6206 LDO 是否被绕过：

| 屏幕 VCC 接法 | J1 | 说明 |
|---|---|---|
| 接 **5V** | 断开 | 5V 经 LDO 降压到 3.3V |
| 接 **3.3V** | **短接** | 本项目用这种，绕过 LDO |

- 本项目 VCC 接开发板的 **3V3**（按上表，这种情况下 J1 应为短接）。
- 开箱先用万用表蜂鸣档量「VCC 引脚 ↔ 板上 3.3V 点」：导通说明已短接；不导通需要补焊。**本机尚未实测**，实测结果见本节末尾。
- 🚨 **J1 短接后绝对不能再接 5V**，会直接把 5V 加到最后级，烧屏。

> **本机实测（2026-11-08，结论与上表相反）**：
> - 照片放大看 J1 两焊盘像断开的，但**接 5V 时屏幕一直只有背光、无画面**；改接 **3V3 后画面正常**。
> - 理论预期恰好相反（J1 断开就该走 LDO 用 5V），说明 **J1 实际状态未确认**，照片判断不可靠。
> - **当前配置：VCC 接开发板 `3V3`**，已验证可稳定显示。这个接法在 J1 短接或断开两种情况下都不会烧屏（断开时过 LDO 略有压降，实测不影响显示），所以**保持 3V3，不要再接 5V**。
> - 有万用表后建议量一次「VCC 引脚 ↔ 板上 3.3V 点」，把 J1 真实状态补到这里。

## 4. 技术路线图（阶段 0–8）

> 每个阶段都有明确的「做什么 / 验收标准 / 参考」。做完一个就在 §0 打勾。

### 阶段 0 · 环境搭建
> 📖 逐步操作指南（含 macOS 驱动安装、故障排查）：[docs/stage0-setup.md](docs/stage0-setup.md)

**做什么**
1. 安装 Arduino IDE 2.3.x
2. 开发板管理器添加 ESP32 支持（Espressif Systems，装 3.x；若后续编译报错可回退 2.0.17）
3. 安装库：`TFT_eSPI`、`Adafruit AHTX0`、`RTClib`、`ArduinoJson`
4. 选择开发板：`ESP32S3 Dev Module`，设置：
   - Flash Size: 16MB (128Mb)
   - PSRAM: **OPI PSRAM**（N16R8 是 Octal PSRAM，选错会内存不足）
   - Partition Scheme: 16M Flash (3MB APP/9.9MB FATFS)
   - USB CDC On Boot: **Disabled**（本板用 CH343 的 COM 口；开了会看不到串口输出）
   - 另需安装 WCH **CH343 驱动**，否则 macOS 认不到串口

**验收**：不接板子能编译通过 Blink；板子到货后能上传自检程序，串口读出 `Flash 16MB / PSRAM 8MB / ESP32-S3`。

```cpp
#define TFT_CS    10
#define TFT_DC     9
#define TFT_RST    8
#define TFT_BL     7
#define TFT_BACKLIGHT_ON HIGH
#define TOUCH_CS  14         // 启用 XPT2046 触摸
#define SPI_FREQUENCY 40000000       // 单位是 Hz！写成 40000 等于 40kHz，一屏要刷好几秒
#define SPI_READ_FREQUENCY 20000000
#define SPI_TOUCH_FREQUENCY 2500000
#define LOAD_GLCD
#define LOAD_FONT2
#define LOAD_FONT4
#define SMOOTH_FONT
```

2. 跑 `TFT_eSPI` 示例 `Graphicstest`
3. 设置 `tft.setRotation(1)` 转为横屏 320×240

**验收**：颜色正确、无花屏、无偏移；旋转后方向正确。

**常见问题**：白屏 → 检查 BL 是否拉高、CS/DC 是否接反；花屏 → `SPI_FREQUENCY` 降到 27000000 甚至 20000000；颜色反了 → 打开 `TFT_RGB_ORDER TFT_BGR`。

> ⚠️ **本机实测坑（2026-11-08）**：`SPI_FREQUENCY` 单位是 **Hz**。写成 `40000` 会被当成 40 kHz——屏幕能正常显示但**一屏填充要 ~10 秒**（改对后 32 ms）。同理 `SPI_READ_FREQUENCY`/`SPI_WRITE_FREQUENCY`。

### 阶段 2 · WiFi + NTP 时钟
**做什么**
1. 连接 WiFi（把 SSID/密码放到 `secrets.h`，不要硬编码进主文件）
2. `configTime(8 * 3600, 0, "ntp.aliyun.com", "pool.ntp.org")` 获取北京时间
3. 用 `struct tm` 格式化显示：`2026-11-06  周四  14:30:25`
4. 每秒刷新，用 **sprite 双缓冲**或局部擦除避免闪烁
5. 断网重连逻辑（WiFi 断开后自动重试）

**验收**：上电 10 秒内显示正确北京时间；秒数平滑跳动不闪烁；拔掉路由器后时间继续走、恢复后自动重连。

### 阶段 3 · 天气 + 日历
**做什么**
1. 注册天气 API（推荐**和风天气 QWeather** 免费订阅，或心知天气 / OpenWeatherMap）
2. `HTTPClient` 发 GET → `ArduinoJson` 解析
3. 显示：当前温度、天气现象、今日最高/最低、未来 3 天
4. 缓存上次成功数据到 NVS，断网时显示缓存并标注"离线"
5. 刷新频率：30 分钟一次（免费额度有限）
6. 日历：`struct tm` 算星期；农历可接现成库或先不做

**验收**：天气数据与手机 App 一致；断网后显示上次数据；连续运行不掉线。

**注意**：API Key 放 `secrets.h`，该文件不分享、不上传。

### 阶段 4 · 温湿度 + RTC
**做什么**
1. I2C 扫描确认 `0x38` / `0x68`
2. 读 AHT20，显示室内温度湿度
3. DS3231 作为 NTP 失败时的兜底时间源；联网时用 NTP 校准 RTC

**验收**：温湿度与家用温湿度计误差 ≤ 0.5°C；断网重启后时间仍正确。

### 阶段 5 · UI 美化（LVGL + 中文字体）
**做什么**
1. 引入 **LVGL 9**（Arduino 库或 PlatformIO）
2. 设计主界面：大字号时间居中、日期天气在上、温湿度在下
3. **中文字体**（关键难点，TFT_eSPI 自带字体不含中文）：
   - 用 LVGL 在线字体转换器，选思源黑体/文泉驿，只导出需要的字符集（数字 + 常用汉字 + 天气词）
   - 生成 16px / 24px / 48px 三档
4. 加简单动画（秒针、天气图标淡入）
5. 用 FreeRTOS 拆任务：UI 刷新、网络、传感器各一个任务

**验收**：中文正常显示不乱码；界面无闪烁；CPU 占用合理（串口打印 `uxTaskGetSystemState` 观察）。

### 阶段 6 · 音频回环
**做什么**
1. 用 ESP32 Arduino I2S API 配置两路 I2S（一路 RX 接 INMP441，一路 TX 接 MAX98357A）
2. 录 3 秒音频到内存/PSRAM → 原样播放
3. 调采样率（16kHz）、增益，消除爆音
4. 按键触发录音

**验收**：按下按键说话，松手后能清晰回放自己的声音，无明显杂音/爆音。

**注意**：麦克风与喇叭物理隔开 ≥ 5cm，否则啸叫。

### 阶段 7 · 大模型语音助手
**推荐路线：直接跑开源项目 `xiaozhi-esp32`（小智 AI）**

- 仓库：`https://github.com/78/xiaozhi-esp32`
- 它已实现：唤醒词（ESP-SR WakeNet）→ 录音 → WebSocket 上传 → 大模型 → TTS 播放 → 屏幕表情/字幕
- 支持"自定义开发板"配置：在 `main/boards/` 下新建目录，填自己的引脚定义即可
- **注意工具链切换**：这个项目用 **ESP-IDF 5.x**，不是 Arduino。阶段 6 完成后单独装 ESP-IDF，不要试图混在 Arduino 工程里
- 服务端可用官方 `xiaozhi.me` 免费额度，或自建

**做什么**
1. 安装 ESP-IDF 5.x + VS Code 插件
2. 克隆项目，编译官方支持的某块板子，确认能跑通
3. 复制一份 board 配置，改成你的引脚（屏：§3.1；麦：4/5/6；功放：15/16/17）
4. 配置 WiFi 和服务器地址
5. 联调：唤醒词 → 提问 → 回答

**验收**：说"你好小智"能唤醒；问"今天天气怎么样"能语音回答；屏幕同步显示对话文字。

**备选路线（更 DIY、更简单但效果差）**：Arduino 里自己调云端 ASR（百度/阿里）+ LLM API + TTS，HTTP 串起来。适合想完全掌控流程的人，但唤醒词和回声消除要自己处理，工作量大很多。

**做什么**

## 6. 避坑清单

| # | 坑 | 现象 | 解决 |
|---|---|---|---|
| 1 | 买了没有 PSRAM 的 S3 | 语音阶段内存不够、唤醒词跑不起来 | 必须 N16R8，Arduino 里开 OPI PSRAM |
| 2 | 排针没焊/杜邦线松动 | 花屏、随机重启、I2C 掉设备 | 买已焊排针；最终组装焊接固定 |
| 3 | 用芯片内置温度传感器 | 温度比实际高 5–10°C | 必须外接 AHT20/SHT30 |
| 4 | 功放和主控共用 3.3V | 喇叭一响就重启 | 功放接 5V，加 100–470µF 电容 |
| 5 | 麦克风离喇叭太近 | 啸叫 | 隔开 ≥5cm，加泡棉隔断 |
| 6 | TFT_eSPI 引脚没改 | 白屏 | 检查 `User_Setup.h`，确认 BL 拉高 |
| 7 | 中文乱码 | 显示方块/问号 | LVGL 自定义字体，只导出需要的字符集 |
| 8 | 时区错误 | 时间差 8 小时 | `configTime(8*3600, 0, ...)` |
| 9 | API Key 写进主文件 | 泄露 | 放 `secrets.h`，不分享 |
| 10 | 想用 Arduino 跑 xiaozhi | 编译不过 | 语音阶段切 ESP-IDF 5.x |
| 11 | 屏幕常亮烧屏 | OLED 才有此问题 | 选 IPS，不要 OLED |
| 12 | 外壳开孔用热风枪 | 塑料变形 | 美工刀 + 锉刀 |
| 13 | `SPI_FREQUENCY` 单位写成 kHz | 屏幕能显示但一屏刷 10 秒 | 单位是 **Hz**：`40000000`（40MHz） |
| 14 | esp32 core 3.x + TFT_eSPI 不加 `USE_FSPI_PORT` | 一调 `tft.init()` 就 StoreProhibited 重启 | User_Setup.h 里加 `#define USE_FSPI_PORT`（S3 的 `FSPI=0`，新版 `REG_SPI_BASE` 会返回 0） |
| 15 | VCC 接错（J1 短接还接 5V） | 烧屏 | 先量 J1：断开→VCC 接 5V；短接→VCC 接 3V3 |
| 16 | 凭照片判断 J1 状态就上电 | 3.3V 轨被灌 5V，显示/触摸 IC 当场损坏，**背光却还亮着**，极易误判为"屏是好的" | 必须用万用表量 VCC 与板上 3.3V 点是否导通；不确定就先接 **3V3**（J1 短接时正确，断开时电压略低但不烧件） |
| 17 | 只看背光判断屏幕好坏 | 背光只证明供电和 LED 正常，与显示 IC 是否工作无关 | 判断标准必须是**能否显示画面** |
| 18 | 黑屏就先怀疑模块坏了 | 本次为此白排 2 小时，还得出"换屏"的错误结论；实际是**杜邦线/面包板接触不良**，重插就好 | 顺序：① 全部拔下重插、换面包板孔位 ② 换一根杜邦线 ③ 降 SPI 频率重试 ④ 再怀疑模块。**没有仪器排除接触问题前，不要下"硬件损坏"结论** |
| 19 | VCC 供电方式凭照片定 | 本机 J1 拍照看是断开的，但接 5V 一直黑屏、接 3V3 正常，与 §3.5 理论相反 → 照片判断不可靠 | 当前**只用 3V3**（已验证可显示，且两种 J1 状态下都不会烧屏）。换供电前必须用万用表量通断 |
| 20 | 用 `while` 循环等 WiFi 连上 | 断网时每次重试把 `loop()` 卡死 15 秒，**表盘定住不动**，日志里出现整 15 秒空档 | 连接改成"只发起、不等待"的状态机：`WiFi.begin()` 后立刻返回，结果在 `loop()` 里轮询。本例改动后 300 秒记录**零卡顿** |
| 21 | 断网时打印 `WiFi.RSSI()` | 未连接时返回 0，串口打成 `RSSI 0 dBm`，看着像信号极差 | 未连接时打印 `WiFi --` |
| 22 | 以为 `getTouchRaw()` 的返回值能判断按下 | TFT_eSPI 注释写明"Always returns true"，永远为真 | 用 **`getTouchRawZ()` 压力值**判按下，本屏阈值取 400 |
| 23 | 触摸坐标直接用 raw 值 | `setRotation(1)` 后 TFT_eSPI 不会自动交换触摸轴；本屏实测 **X/Y 交换 + 双向反相**（raw y 越大越靠左，raw x 越大越靠上） | 必须自己做映射：`screenX = map(rawY, 640,3650, 320,0)`、`screenY = map(rawX, 640,3650, 240,0)`，用"打点跟手指对不对"验证 |
| 24 | 抓串口日志时按时间戳过滤陈旧数据 | 过滤器把**不带时间戳的行**全丢了（阶段 1 自检固件的日志全是没有时间戳的），抓取结果只剩表头，误以为板子死机 | 过滤规则必须默认保留：只有"带时间戳且比抓取起点早"的行才丢；无时间戳的行一律保留 |
| 25 | 想给数码管加"斜角" | 整字倾斜（shear）看起来歪，不是想要的 | 用户要的是**笔画端部一点点圆角、整体仍方**：用 `fillRoundRect(x,y,w,h,4,color)` 画每一段，不要做坐标倾斜 |
| 26 | 直接解析和风天气的 HTTP 响应体 | 响应**永远是 gzip**（实测发 `Accept-Encoding: identity` 也压缩，头两字节 `1f 8b`），按 JSON 找 `"code"` 必然失败且不报错 | ESP32 的 HTTPClient 不解压。用 ROM 的 `#include <miniz.h>` + `tinfl_decompress_mem_to_mem(..., TINFL_FLAG_USING_NON_WRAPPING_OUTPUT_BUF)`：先跳过 10 字节 gzip 头与可选扩展字段、再掐掉尾部 8 字节，按 raw deflate 解 |
| 27 | TLS 任务栈按普通任务给 8KB | 每连一次 HTTPS 就 `Stack canary watchpoint triggered (xxx)` + 整机重启 | mbedTLS 握手要 10KB 以上，**HTTPS 任务栈给 16384** |
| 28 | 在 `.ino` 里定义结构体并当函数参数 | Arduino 自动生成的函数原型被插到 include 之后、结构体定义之前，报 `'WeatherData' was not declared` | 在 include 之后写一行 `struct WeatherData;` 前置声明 |
| 29 | 每秒整条清屏再全量重画 | 秒针每跳一次，屏幕明显"闪一下" | 记住上一帧字符串做 **diff**，只重画变化的格子；整条清屏只在布局变化时做 |
| 30 | 背光用 `digitalWrite` 闪三下当开机动画 | 观感像故障自检，很丑 | 用 `ledcAttach(TFT_BL, 5000, 8)` + `ledcWrite()` 做亮度淡入；期间先画完画面再点灯 |
| 31 | 用固定串 `"loc":"` 解析 ipinfo.io 返回 | 一直 `auto location failed`，但 HTTP 是 200；日志里 body 只有 265 字节、首字符 `{` | ipinfo 返回的是**美化 JSON**（`"loc": "39.9110,116.3950"`，冒号后有空格）。解析时跳过冒号前后的空白/换行，或统一用容忍空白的 `jsonStr()` |
| 32 | 小字号里用 `'°'` 当温度单位 | 屏幕出现乱码方块，甚至盖住旁边的字 | TFT_eSPI 内置字体 2/4/6 只有 **ASCII 32..127**（96 个字形），`'°'`(0xB0) 越界。小字改用 `-2/7` 这种纯数字格式；要大号"度"就手绘小圆圈（`drawTemp()`） |
| 33 | 顶栏文字从长串切成短串时只重画新字 | 从 `RH 28%` 切到 `OFF` 后，左边残留 `H 28` 的像素 | 这段文字是**不透明**画的，短串盖不住长串。切换前先 `fillRect()` 清掉整个文字区（本机 x=226..284、y=6..34） |
| 34 | 想用 TFT_eSPI 内置字体显示中文 | 内置字体 2/4/6 只有 ASCII，中文画不出来；LVGL 字库又太重 | 只需少量汉字时，用 Pillow 从系统圆角字渲染成 **1-bit 掩码**，生成迷你字库（本机 `tools/gen_wx_font.py` → `wx_font.h`，14px、16 字形约 3.4KB），固件只画笔画像素 |
| 35 | 天气任务和 NTP 同时发 DNS | 偶发 `assert failed: udp_new_ip_type ... Required to lock TCPIP core functionality!` 后整机重启，backtrace 在 `sntp_dns_found → dns_gethostbyname` | 串行化：记录 `configTime()` 时刻，天气任务首次等 NTP 对时完成（最多 15s）再请求，之后每次 `configTime()` 的 8 秒内不发请求 |
| 36 | 小字号中文用灰度抗锯齿 | 笔画周围一圈半透明灰边，在屏上看着像**字体阴影/发虚** | ≤14px 时按 α≥128 二值化成 1-bit 掩码；圆角仍由字体形状保证，不需要灰度边缘 |
